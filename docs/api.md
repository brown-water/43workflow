# api.md

This document outlines the connectors, endpoints, inputs, outputs, and integration rules that bridge the secure Navy IT Mainframe with the local client-side Reconciliation Engine (the Master Planner).

---

## 1. Zero-Install "Read Bridge" Concept

Because the Master Planner runs entirely locally within browser sandboxes via `file://` or restricted intranet pages to accommodate strict IT managed-device environments, it cannot execute direct HTTP APIs to secure mainframe systems. 

Instead, it relies on a **Zero-Install Local File Ingestion API**:
*   **Source:** Flat-file dumps extracted from the mainframe (OAIS) and fitness report databases (BOL/NSIPS).
*   **Watch Folder:** A local OneDrive/SharePoint synced directory.
*   **Consumption Method:** Direct file drop, client-side drag-and-drop ingestion, or local Power Query preprocessing.

---

## 2. Inbound Data Formats

### A. Mainframe Personnel Data (OAIS State)
*   **File Format:** Delimited Flat File (`SUPPLY_sYNTH.txt`) using either `%` or `?` as field separators.
*   **Frequency:** Daily extract.
*   **Key Fields & Mappings (`headers.csv` API contract):**

| Legacy Mainframe Column | Target JSON State Property | Purpose & Integration Rules |
| :--- | :--- | :--- |
| `ICOMM.SCRN.RSLT` | `commandScreenResult` | Captures Command Screen Results (CSR) for selection boards. |
| `IULT.AUIC` | `ultimateUic` | Gaining Unit Identification Code for slated assignments. |
| `IULT.EDA` | `estimatedDateArrival` | Gaining Unit Estimated Date of Arrival (EDA). |
| `IPRD` | `projectedRotationDate` | Current projected rotation date; baseline for the slate. |
| `BAQD` / `IAQD` | `additionalQualifications` | Array of mapped qualification keys (e.g., `2D1` for Air Safety Officer). |
| `BSUBSPEC` / `ISUBSPEC`| `subspecialties` | Officer functional subspecialties. |

### B. Fitness Report Data (FITREP Continuity)
*   **File Format:** Comma-Separated Values (`SUBEVAL_DDMMYY.csv`).
*   **Frequency:** Occasional batch export or scrape.
*   **Schema Fields:**

| Property | Data Type | Description |
| :--- | :--- | :--- |
| `dodId` or `ssn` | `String` | Primary identifier for reconciliation joins. |
| `reportingSeniorName`| `String` | Name of the rating officer. |
| `rsUic` | `String` | Unit Identification Code of the rating officer. |
| `rsca` | `Float` | Reporting Senior Cumulative Average (the rating baseline). |
| `ita` | `Float` | Individual Trait Average (officer's score). |
| `reportFromDate` | `Date` | Start of FITREP period. |
| `reportToDate` | `Date` | End of FITREP period. |
| `promotionRecommendation`| `String` | EP, MP, P, PR, or SP. |
| `summaryGroupSize` | `Integer` | Total competitive group count. |

## 3. Transformation & Ingestion Pipeline

The ingestion pipeline transforms raw mainframe and FITREP strings into unified application state:

```
[Raw Delimited Files] ➔ [Power Query / Local Script Parsing] ➔ [Master JSON / CSV Ingestion]
```

### Transformation Rules
1.  **Delimited Extraction:** Convert the `%` or `?` separated variables into normalized rows.
2.  **Date Standardizing:** Parse legacy date strings (e.g., `DDMMYY` or `YYMMDD`) into ISO-8601 strings (`YYYY-MM-DD`).
3.  **Relative Value Calculation (API Level):**
    $$\text{Relative Value (RV)} = \text{ITA} - \text{RSCA}$$
    If $\text{RV} > 0$, the officer is "Above the Nut" (positive performance trajectory).
4.  **Duration Ingestion:**
    $$\text{Report Duration (Months)} = \frac{\text{reportToDate} - \text{reportFromDate}}{30.4}$$
    Calculated field used in sorting competitive performance ties during slating.

---

## 4. Reconciled Outbound Output (`state.json` contract)

The final output is generated by merging OAIS and FITREP states.

### Reconciliation Diff Rules:
*   **Rule 1 (PRD Shift):** If `intentState.prd` $\neq$ `oaisState.prd`, raise a `SYNC_REQUIRED` alert labeled `"PRD Drift"`.
*   **Rule 2 (Manning Gap):** If `oaisState.estimatedDateArrival` shifts past the incumbent's `oaisState.projectedRotationDate`, flag an active manning gap with the calculated duration in days.
